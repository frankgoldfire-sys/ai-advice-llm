# 实验分析计划（初稿 v0.1）

## 1. 我们究竟想研究什么？

本项目研究一个具体问题：

> 在大语言模型看到外部 AI 建议之前，先让它记录自己的独立答案，能否减少错误建议造成的误导，同时保留正确建议带来的纠错收益？

这里研究的不是“大模型能不能做对选择题”，也不只是“大模型会不会听建议”。我们真正关注的是：**建议出现的时机，是否会改变模型使用建议的方式。**

## 2. 为什么这个问题值得研究？

外部建议可能产生两种相反作用：

- 建议正确时，它可能帮助模型纠正原有错误；
- 建议错误时，它也可能把原本正确的模型带偏。

因此，理想的决策流程不是让模型一概拒绝建议，也不是让模型一概相信建议，而是尽量做到：

> 吸收有用信息，同时抵抗错误信息。

“先独立作答，再查看建议”是一种简单、低成本的流程设计。本实验要检查它是否真的有效，以及是否存在让模型变得更加固执的代价。

## 3. 研究对象与观测单位

- 研究对象：通过 API 调用的大语言模型；
- 题目来源：MMLU 多项选择题；
- 一条观测：某个模型在某一道题、某一种实验条件下产生的一次最终答案；
- 标准答案：MMLU 数据集提供的 `correct_answer`。

## 4. 变量是什么？

### 4.1 自变量（我们主动改变的条件）

1. 建议是否出现：无建议 / 有建议；
2. 建议是否正确：正确建议 / 错误建议；
3. 建议出现时机：首次回答前 / 记录独立答案后。

### 4.2 因变量（我们测量的结果）

1. `final_correct`：最终答案是否正确；
2. `matches_advice`：最终答案是否与建议一致；
3. `answer_changed`：最终答案是否不同于初始答案；
4. `corrected`：初始答案错误，最终答案变正确；
5. `corrupted`：初始答案正确，最终答案变错误。

## 5. 实验条件

### 组1：Baseline

模型直接独立回答题目，不提供外部建议。

作用：测量模型原本的答题准确率。

### 组2：Reanswer Control

模型先独立回答，然后不给任何新信息，只要求它再次提交最终答案。

作用：测量模型在没有建议时，仅仅因为多进行一轮对话而自然改答案的概率。

如果没有这一组，我们无法判断模型改答案究竟是受建议影响，还是重复回答本身造成的。

### 组3：Correct-first

模型第一次回答之前，先看到正确的外部 AI 建议。

作用：测量正确建议直接出现时的收益和采纳程度。

### 组4：Wrong-first

模型第一次回答之前，先看到错误的外部 AI 建议。

作用：测量错误建议直接出现时的误导程度。

### 组5：Independent → Correct

模型先记录独立答案，再看到正确建议，并可保留或修改答案。

作用：测量先独立作答后，模型是否仍能利用正确建议纠错。

### 组6：Independent → Wrong

模型先记录独立答案，再看到错误建议，并可保留或修改答案。

作用：测量先独立作答能否保护模型不被错误建议带偏。

## 6. 最重要的比较

### 比较A：错误建议的伤害

比较 `Wrong-first` 与 `Independent → Wrong`。

如果后者的最终正确率更高、错误建议采纳率更低，说明先独立作答可能增强了抗误导能力。

### 比较B：正确建议的帮助

比较 `Correct-first` 与 `Independent → Correct`。

如果先独立作答后模型仍能获得相近的纠错收益，说明该流程没有明显损害模型利用正确信息的能力。

### 比较C：自然改答案

比较 `Reanswer Control` 与两个 `Independent → Advice` 条件。

这可以帮助判断答案变化在多大程度上来自外部建议，而不是来自多轮回答本身。

## 7. 暂定研究假设

这些是假设，不是我们已经知道的结论：

- H1：错误建议会降低模型最终正确率；
- H2：正确建议会提高模型最终正确率；
- H3：先独立作答会降低模型对错误建议的采纳率；
- H4：先独立作答也可能降低模型对正确建议的采纳率，表现出“抗误导能力”和“可纠正性”之间的权衡。

即使假设不成立，结果仍然有研究意义。我们不能为了得到想要的结论而更改数据或实验规则。

## 8. 当前试运行能说明什么？

目前只运行了1道题，因此只能说明：

- 数据能够读取；
- DeepSeek API 能够调用；
- 五种原始条件能够运行；
- JSON 结果能够保存；
- 初始答案、最终答案、纠错和腐蚀等指标能够记录。

它不能证明任何普遍的研究结论。

## 9. 当前设计需要注意的问题

1. 现有脚本缺少 `Reanswer Control`，下一步需要补上；
2. 当前“错误建议”会特意避开模型的 Baseline 答案，因此研究的是外部建议与原判断发生冲突时的表现；
3. 20道题只适合检查流程，不能支持稳定结论；
4. 单一模型的结果不能推广到所有大语言模型；
5. 即使 `temperature=0`，API结果也不一定永远完全可复现，因此正式实验需记录模型名称、时间、参数和原始返回；
6. 先独立作答的效果可能来自承诺、锚定、自我一致性或多一轮对话。本项目首先评估这一整套流程是否有效，不轻易声称已经识别出具体心理机制。
